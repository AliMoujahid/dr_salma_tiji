1. PRESENTATION GENERALE & OBJECTIFS DU LOGICIEL
====================================================================================================
L'application "Cabinet Dentaire Dr. Salma Tijini" est un système ERP/Dossier Patient Informatisé (DPI) 
médical complet, autonome, ultra-performant et conçu sur mesure pour la pratique de la médecine dentaire.

Principaux objectifs :
- Digitalisation à 100% du cabinet : Fin des fiches papier, dossiers d'antécédents perdus et calculs manuels.
- Suivi clinique de pointe : Schéma dentaire 3D interactif visualisant l'arcade maxillaire et mandibulaire 
  avec l'état précis de chaque dent et surface.
- Pont matériel direct avec les capteurs radiologiques dentaires USB (NanoPix / capteurs CMOS).
- Automatisation de la relation patient : Envoi de rappels de rendez-vous et consignes post-opératoires via WhatsApp Web.
- Rigueur financière : Suivi du "Diftar" (carnet financier des soins et versements au centime près) et 
  édition de factures conformes à la réglementation marocaine (ICE, IF, N° Ordre, arrêté de compte en lettres).
- Fonctionnement 100% autonome et sécurisé : Données stockées localement sur le PC du cabinet (Offline-First), 
  aucune dépendance au cloud, verrouillage anti-copie par empreinte matérielle, et sauvegardes quotidiennes automatiques.

====================================================================================================
2. ARCHITECTURE TECHNIQUE & STACK TECHNOLOGIQUE
====================================================================================================
A. FRONTEND :
- Framework : React 19 + TypeScript + Vite.
- Routage : React Router v7.
- Stylisation : Tailwind CSS + CSS Variables personnalisées (Thème moderne Médical Sombre/Clair, Glassmorphism).
- Graphismes 3D : Three.js + @react-three/fiber + @react-three/drei (Moteur 3D temps réel pour les dents et arcades).
- Icônes : Lucide React.
- Requêtage & Cache : TanStack React Query.
- Impression & Rendu Documentaire : CSS @media print sur mesure + html2canvas + jsPDF.

B. BACKEND :
- Environnement : Node.js (v20+ / v22+) + Express + TypeScript.
- Base de données : MongoDB Community Server (Mongoose ODM).
- Sécurité : JWT (JSON Web Tokens), bcrypt pour le hachage des mots de passe, Middlewares de sanitisation et de rôles.
- Automatisation WhatsApp : puppeteer-core + whatsapp-web.js (Pilotage Chromium sans API payante Meta).
- Gestion des fichiers : Multer (stockage local partitionné par patient et catégorie).
- Tâches de fond : Node-cron (Sauvegardes quotidiennes à 23h00, rappels automatiques à 09h00 et 17h00).

C. INFRASTRUCTURE & RESEAU :
- Gestionnaire de processus : PM2 en tâche de fond Windows invisible (démarrage automatique avec Windows).
- Mode multi-postes (LAN) : Serveur accessible via l'adresse IP locale (ex: http://192.168.1.50:5000) 
  depuis n'importe quel second PC (secrétariat/accueil) ou tablette sans rien installer sur les autres postes.

====================================================================================================
3. SYSTEME DE LICENCE MATERIELLE & DEPLOIEMENT RESEAU LOCAL
====================================================================================================
- Empreinte Matérielle (Machine ID) : Calculée à partir du processeur (CPU ID), carte mère (Motherboard UUID) 
  et premier disque dur physique via des requêtes WMI Windows.
- Clé de licence cryptographique : Algorithme HMAC-SHA256 utilisant un secret privé développeur.
- Contrôle de validité : L'application vérifie la licence à chaque démarrage et toutes les heures. 
  Si la licence est invalide ou absente, l'écran est bloqué par la modale "LicenseActivationModal".
- Générateur Développeur : Script sécurisé dans `DEVELOPER_TOOLS/generate_license.js` pour émettre des clés d'activation.

6. STRUCTURE DE LA BASE DE DONNEES (MODELES MONGOOSE)
====================================================================================================
1.  User                  : Comptes utilisateurs, rôles (admin, doctor, assistant), hash mot de passe, avatar.
2.  Patient               : État civil, CIN, téléphone, date de naissance, groupe sanguin, antécédents, mutuelle.
3.  Appointment           : Date, heure début, heure fin, patientId, motif, statut, notes, rappel WhatsApp envoyé.
4.  Treatment             : Acte réalisé/prévu, patientId, dentNum, prix, statut (planned, completed), date.
5.  ToothHistory          : Historique clinique par dent (11-48, 51-85), état global, faces atteintes, observations.
6.  Invoice               : Numéro de facture, patientId, liste des items, montant HT, TVA, Total TTC, mode paiement.
7.  Payment               : Versement financier, patientId, montant, mode (espèces, chèque, TPE), date, référence.
8.  DentalAct             : Catalogue officiel des soins du cabinet, code, catégorie, libellé, tarif de base.
9.  Document              : Pièce jointe patient, chemin de fichier, catégorie (radio, ordonnance, analyse, devis).
10. NotificationLog       : Trace de chaque message WhatsApp envoyé, patientId, contenu, statut de distribution.
11. NotificationSettings  : Configuration des horaires d'envoi et modèles de messages WhatsApp.
12. ClinicConfig          : Données d'identité du cabinet, logoUrl, stampUrl, ICE, IF, adresse, téléphones.
13. AuditLog              : Piste d'audit légale (qui a créé, modifié ou supprimé une donnée médicale avec horodatage).
14. FollowUpReminder      : Rappels périodiques de contrôle ou de détartrage (ex: rappel automatique à 6 mois).
15. MessageTemplate       : Modèles personnalisables de messages texte.
16. WhatsAppReceivedMedia : Médias et photos reçus des patients par WhatsApp (radios envoyées à distance).
